# 悬浮供电 · 参数说明

> 把充电电流钳到 ≈ 系统功耗，让电池不充不放（伪旁路）。
> 配置文件：`/data/adb/modules/MiFloatCharge/config.conf`
> 改完不用重启，下一个采样周期自动生效。

---

## 一、先理解它怎么工作

每经过一个**周期**（`SAMPLE_WINDOW` 秒），它会做这几件事：

```
周期开始
  ├─ 采 1 次电流 ──等待──→ 采 2 次 ──等待──→ … → 采满 N 次
  │      ↑ 每次间隔 = SAMPLE_WINDOW ÷ SAMPLE_COUNT
  │
  ├─ 求这 N 次的平均值 avg（µA，负=充电，正=放电）
  │
  ├─ 判断方向：
  │     avg < -死区  →  还在充，电流上限 CM 减一个步长
  │     avg > +死区  →  在放电，电流上限 CM 加一个步长
  │     落在死区内   →  不动（已经稳了）
  │
  ├─ 限幅到 [MIN_CM, MAX_CM]
  │
  └─ 写 1 次 constant_charge_current_max
```

**关键点**：周期内采很多次是为了平均掉噪声，但**只写 1 次**，所以写入次数跟 `SAMPLE_WINDOW` 成反比——周期越长越省电，但对负载变化反应越慢。

## 二、参数详解

| 参数 | 默认 | 范围 | 作用 | 调大 | 调小 |
|---|---|---|---|---|---|
| `ENABLED` | `0` | 0/1 | 总开关。0 = daemon 完全不运行（零占用） | — | — |
| `SAMPLE_WINDOW` | `60` | 10~3600 | **多久写一次电流**（秒） | 省电、写入次数少，但反应慢 | 反应快、更贴合实时功耗，但写得多 |
| `SAMPLE_COUNT` | `5` | 1~30 | 每周期采几个点。**间隔 = WINDOW ÷ COUNT** | 平均更平滑、抗噪声 | 间隔拉长，单点噪声影响变大 |
| `DEADBAND_MA` | `50` | 5~500 | **死区**。平均净电流落在 ±此范围内就不调整 | 更稳、不乱跳，但允许偏差更大 | 更精确，但容易来回抖 |
| `STEP_MA` | `30` | 5~500 | 每次调整的幅度 | 收敛快，但容易过冲震荡 | 平滑细腻，但收敛慢 |
| `MIN_CM_MA` | `50` | 0~2000 | **算法输出 CM 的下限**，可设 0；低于 ~40mA 驱动会放弃充电、滑入断充 | 更保守，但离零点更远 | 允许设 0，但低于 ~40 会掉电（驱动行为，模块不拦） |
| `MAX_CM_MA` | `500` | 50~20000 | **电流上限**。防止反馈一路推高导致大量充电 | 允许更大电流（小心充过头） | 更安全，但收敛范围受限 |
| `BATT_MAX` | `95` | 50~100 | 电量达到此值后不再往上推（保持悬浮） | 能充得更高 | 更早停在悬浮状态 |
| `BATT_MIN` | `20` | 5~60 | 电量低于此值暂停悬浮，优先充满 | 更早进入悬浮 | 更低电量才启用（更保守） |
| `LOG_MAX_LINES` | `400` | 50~5000 | 日志保留行数，超出自动截断 | 能查更久的历史 | 更省空间 |

### 单位说明

| 后缀 | 含义 | 例子 |
|---|---|---|
| `_MA` | 毫安（mA） | `STEP_MA=30` → 每次调 30mA |
| `_WINDOW` | 秒 | `SAMPLE_WINDOW=60` → 60 秒一个周期 |
| 百分比 | % | `BATT_MAX=95` → 95% |

> 内部实际写入节点的单位是 **µA**，模块自动 ×1000 换算，配置里统一写 mA 就行。

## 三、常见调法（直接抄）

| 场景 | 配置 | 效果 |
|---|---|---|
| **默认省电** | `WINDOW=60 COUNT=5` | 每 12 秒采 1 次，每分钟写 1 次 |
| **响应快**（打游戏、负载剧烈变化） | `WINDOW=30 COUNT=10` | 每 3 秒采 1 次，30 秒调 1 次 |
| **极省电**（挂机、看小说） | `WINDOW=300 COUNT=5` | 每 60 秒采 1 次，5 分钟调 1 次 |
| **怕抖**（净电流来回跳） | `DEADBAND=100` `STEP=20` | 死区放宽 + 步长减小 |
| **收敛太慢**（等很久才稳） | `DEADBAND=30` `STEP=60` | 死区收紧 + 步长加大 |
| **想更贴近零** | `DEADBAND=20` `STEP=10` | 精度提高，但可能小幅震荡 |
| **电池养护优先** | `BATT_MAX=80` | 充到 80% 就停住悬浮 |
| **夜间长时间挂机** | `BATT_MAX=85` `BATT_MIN=80` | 到 85 断电，掉到 83 才恢复，不会 89↔90 横跳 |
| **插电要立刻响应** | `PLUG_POLL=5` | 没插电时每 5 秒查一次（默认 30 秒省电） |

### 死区与步长的关系

```
死区太小 + 步长太大  →  来回震荡（电流上限一上一下跳）
死区太大 + 步长太小  →  永远调不到位（一直在死区外，但每次只挪一点点）
```

默认 `50 / 30` 是实测调出来的平衡点，一般不用动。

## 四、怎么判断工作正常

看日志（WebUI 底部，或 `/data/adb/MiFloatCharge/float.log`）：

```
cap=93% avg=13.8mA cm=50.0mA adj=0
       ↑            ↑          ↑
       电量    平均净电流   调整方向
                (正=充电)  0=不动 / 1=加大 / -1=减小
```

净电流符号和界面一致：**正=充电、负=放电**（节点原始值相反，日志里已翻转）。
日志单位统一为 mA，保留一位小数。

**健康状态**：

- `adj=0` 连续出现 → 已进入死区，稳定悬浮
- `avg` 在 `±DEADBAND_MA` 范围内 → 正常
- 电量基本不动 → 电池真的没在充放电

**异常情况**：

| 现象 | 原因 | 处理 |
|---|---|---|
| `avg` 一直是很大的负数（-1A 以上） | 电流上限被推得太低，还在大电流充 | 正常过渡期，等几个周期；或把 `MIN_CM_MA` 调大些 |
| `adj` 在 1 和 -1 之间反复跳 | 死区太小 / 步长太大 | 加大 `DEADBAND_MA` 或减小 `STEP_MA` |
| 电量一直涨 | 悬浮没生效，`MAX_CM_MA` 太大 | 减小 `MAX_CM_MA` |
| 电量一直掉 | CM 低于约 50mA 触发驱动断充 | 把 `MIN_CM_MA` 调到 50 以上（下限是你设的值，不是固定 50） |
| 刚启动/重新插电后头一分钟 `adj=0`、CM 不动 | 初始化后刻意保持 60 秒，等 PD 协商稳定再采样 | 正常，不是卡住；保存设置/切预设会跳过这段等待 |
| 电量到顶断电后要掉几格才恢复 | 恢复迟滞 `BATT_MAX − 2` | 正常，为避免夜间 89↔90 横跳 |
| 日志出现 `WARN 写CM失败` | 驱动拒绝了写入 | 节点被系统锁了，重新开关一次 |
| 日志出现 `未插电，暂停` | 充电器没插 | 正常行为，插上自动开始（检测周期由 `PLUG_POLL` 控制） |

| 显示 | 取自 | 说明 |

## 七、原理补充：为什么这样能"伪旁路"

平板的供电拓扑是：**适配器 → 充电 IC → 电池 → 系统负载**（电池和系统并联）。

- 适配器输入电流 = 系统耗电 + 电池充电电流
- 电池净电流 = 充电电流 − 系统耗电

当把 `constant_charge_current_max`（充电电流上限）压到约等于系统耗电时：

```
充电电流 ≈ 系统耗电  →  电池净电流 ≈ 0
电池不充不放，功耗全部由适配器承担
```

**实测数据**（小米平板5 Pro，PD 充电器，屏幕点亮，系统功耗约 370mA）：

| CM 设定 | 电池净电流 | 状态 |
|---|---|---|
| 600mA 以上 | -4.5A | 限流失效，满速快充 |
| 300mA | -268mA | 正常限流 |
| 150mA | -114mA | 正常限流 |
| 100mA | -63mA | 接近零点 |
| **50~80mA** | **+13~15mA** | **悬浮（净电流≈0）** |
| 40mA 以下 | +310mA | 滑入断充 |

> ⚠️ **死区现象**：CM 低于 ~40mA 时，驱动会判定"这点电流不值得充"，直接放弃充电，
> 结果电池反而开始放电（+310mA）。`MIN_CM_MA` 默认 50，但**可以设 0**；
> 设 0 只是允许算法把 CM 写到 0，低电流下的断充/掉电是驱动行为，模块不会替你拦住。
> 另外 WebUI 在读取 0 时可能显示成 50（显示问题，不影响实际写入），以 `config.conf` 为准。

## 八、注意

- 只在插着充电器时工作，拔电自动暂停，插回自动重新初始化
- 关闭模块 / 卸载模块都会把电流上限还原成原值，不会卡在限流状态
- 悬浮状态下电量基本不动；想正常充电就关掉模块
- 部分机型 `constant_charge_current_max` 写入可能被驱动拒绝，日志会有 `WARN`
